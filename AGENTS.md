# Project Management OS Instructions

## Scope

This repository is for public, reusable project execution systems.

Use it for:

- project planning and breakdown
- weekly/monthly reviews
- decision records
- delivery checklists
- Codex operating rules
- automation playbooks
- Sales or outreach workflows when they become real processes

Do not publish private personal schedules, private business leads, customer identities, credentials, or sensitive internal notes.

## Preferred Codex Routing

- Use Plan-style work for complex tasks before editing.
- Use GitHub workflows for repo updates, PRs, issues, CI, and publishing.
- Use automation tools only after a workflow has succeeded manually at least once.
- Use `Documents` for project briefs, proposals, or decision memos.
- Use `Notion` when capturing or retrieving project knowledge from connected workspaces.

## Operating Rules

- Inspect current repo status before broad edits.
- Keep changes scoped to the stated goal.
- If the user steers mid-task, follow the newest instruction immediately.
- Prefer worktrees for parallel experiments.
- Prefer Git rollback for abandoning a whole direction.

## Output Style

- Make next actions obvious.
- Separate plan, status, blockers, and decisions.
- Keep reusable processes in `playbooks/`.
